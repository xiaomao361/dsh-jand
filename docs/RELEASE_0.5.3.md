# dsh-jand 0.5.3

面向「别人装上以后才知道不能用」的三处缺口：平台支持、下载失败原因、上手路径。
内核仍固定 jand 0.5.0，仍先校验归档
SHA-256、再校验二进制 SHA-256。GitHub 下载失败时回退到自有中继上的官方归档副本。

## 变更

- **备用下载源**：GitHub 下载在 15 秒内未完成、传输或 HTTP 失败时，转向 `jand.zhou-wei.com/downloads/jand/v0.5.0/`（最长 120 秒）。两个源都失败仍返回失败及各源错误码；不安全跳转、超限或哈希失败不回退。两次哈希校验和缓存路径保持不变。
- **下载来源可见**：准备成功后在该内核目录写入 `jand.origin.json`（来源未知时不写），
  设置页列出候选来源主机和上次实际使用的来源；该文件写不进去不影响已校验的内核。
  `jand_status` 的 `kernel` 因此多了 `sources` 与 `origin`。
- **索引自检**：新增 `npm run check:mirror`，比对公网 `index.json` 与本包清单；
  `--download --platform win32-x64` 会真实下载并核对归档与解出二进制，
  `--package <tgz>` 核对候选包哈希，避免索引与实际上传的文件不一致。

- **离线导入**：网络完全不可用时，设置页可填写本机官方归档（zip / tar.gz）或解出的
  运行文件绝对路径，走同一套哈希校验后装进正常缓存；只接受与固定版本一致的官方文件，
  修改过的文件、相对路径和目录一律拒绝，来源记为 `import`。
- **下载进度与重试**：准备过程上报阶段（下载 / 校验 / 解包 / 写入）与已收字节，
  设置页在准备期间显示「正在下载 · 1.5 MB / 4.0 MB」；每个来源先自动重试一次
  （1 秒后），仍失败才换下一个固定来源。
- **`jand_guide` 工具**：助手可按主题（overview / download / collaboration / safety）
  读取约 1 千字的受控说明，避免每次从工具描述里猜流程。
- **DSH 兼容基线**：设置页写明兼容性只基于 DSH 0.2.1-rc.5 实测；能读到当前 DSH 版本时
  一并显示，读不到时只陈述基线，不虚报支持范围。
- **内核失败分类（JAND_KERNEL_\*）**：以前所有下载问题都塌缩成
  `Kernel download failed (…)`。现在每次失败带一个稳定代码和一句可执行说明：
  `UNSUPPORTED`、`OFFLINE`、`NETWORK`、`TLS`、`TIMEOUT`、`HTTP`、`REDIRECT`、
  `SIZE`、`ARCHIVE`、`BINARY`、`CACHED`、`WRITE`、`MANIFEST`、`OVERRIDE`、
  `INSECURE`。设置页把代码翻成中文一句，助手拿到的是同一条原因，不再猜。
- **不支持平台提前警示**：`jand_status` 的 `kernel` 增加 `supported`、`signed`、
  `notarized`、`source` 和 `published`。不支持时首页卡片与设置页都在任何协作
  动作之前说明原因，并给出 Windows ARM64 的实际路径（改用 x64 版 DeepSeek
  Harness，由系统模拟运行），而不是等用户点「发起」才报错。
- **签名与来源说明**：设置页内核区按平台显示是否带平台签名；Windows 版明确
  写出没有代码签名，被安全软件拦截时如何加信任。
- **默认中继显式告知**：首页和设置页都写明当前经默认公共中继转发、消息端到端
  加密但运营方可观察连接元数据；切换自建中继的入口保持原位。
- **助手首次使用流程**：注入的系统提示补上 status → prepare → 令牌/邀请两条路
  → arm/inbox/ack/send 的顺序，并规定：内核问题属于本机问题、要说代码和重试
  路径，不得报成对方的问题；不支持平台直接停，不做无意义重试；发起前说明当前
  中继。

## 验证

- `npm test`：76 项通过（7 项本机内核集成用例按设计跳过），新增
  `test/locale.test.js`（中英键对齐、每个错误码都有译文）与 `test/ui.test.js`
  （用迷你 hook 渲染器跑打包后的 `client.js`，断言不支持横幅、默认中继说明、
  未签名说明和下载失败原因确实出现在用户能看到的文字里）。
- Windows 归档未变，本轮重新验证过：官方 zip 4,214,572 字节，归档 SHA-256
  `4c77fd8f…f669f0d72d`，包内 `jand.exe` 10,328,576 字节，SHA-256
  `b3fe0af0…513538f73b6`，与 `kernel/manifest.json` 一致；插件自带的纯 JS
  解压器对该 zip 解出的字节与清单哈希一致。

- `npm run check`、`npm run test:native`（6/6）与本地打包审计通过。
- 真实网络验证：主机可用时走 GitHub；屏蔽 GitHub 后由备用源补齐，解出二进制哈希
  `407db920…30870d` 与清单一致。`check:mirror` 五个平台索引全部一致，
  `--download --platform win32-x64` 从备用源取到 4,214,572 字节、归档与 `jand.exe`
  双重哈希均匹配。
- 新增用例：来源记录（主源/备用源各一）、来源文件不可写不影响已校验内核、
  设置页显示候选来源与实际来源。
- 备用源回归覆盖主源超时、HTTP 失败、双源失败、不安全跳转与损坏归档；失败时不产生可用缓存。

## 未包含

按决定不再做 x64 模拟运行，只保留提前提示。
